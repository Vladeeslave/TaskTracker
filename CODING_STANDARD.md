# Стандарт кодування проєкту TaskTracker

## 1. Загальні положення

1. Стандарт діє для всього C#-коду рішення: проєктів `TaskTracker.Core` і `TaskTracker.App`.
2. Цільова платформа — `net8.0`; версія мови — остання, доступна в SDK (`LangVersion = latest`).
3. Ідентифікатори пишуться англійською, коментарі й XML-документація — українською.
4. Пункт, який не можна однозначно оцінити як «дотримано» або «порушено», до стандарту не входить.
5. Відступ від правила фіксується в `.editorconfig` із коментарем-обґрунтуванням або атрибутом `SuppressMessage` (не більше двох разів на весь проєкт).

## 2. Іменування

| Сутність | Конвенція | Приклад | Антиприклад |
| --- | --- | --- | --- |
| Клас, запис | PascalCase, іменник | `TimeEntry` | `timeentry` |
| Інтерфейс | `I` + PascalCase | `ITaskRepository` | `Repository` |
| Метод | PascalCase, дієслово | `CalculateTotalHours` | `calc` |
| Властивість | PascalCase, іменник | `PlannedHours` | `GetPlannedHours` |
| Приватне поле | `_` + camelCase | `_entries` | `m_Entries` |
| Локальна змінна, параметр | camelCase | `totalHours` | `th` |
| Константа | PascalCase | `MaxEntryCount` | `MAX_ENTRIES` |
| Перелічення | PascalCase, однина | `WorkTaskStatus` | `WorkTaskStatuses` |

Додаткові правила іменування:

1. Скорочень на кшталт `usrCnt` немає; винятком є загальноприйняте `Id`.
2. Булеві властивості починаються з `Is`, `Has` або `Can`: `IsLead`, `IsActive`.
3. Назва типу не збігається з типом простору `System`: `WorkTask`, а не `Task`.
4. Ім'я файлу збігається з іменем типу, який у ньому лежить.

## 3. Форматування

1. Відступ — 4 пробіли; табуляція заборонена. У `.csproj`, `.props`, `.json`, `.yml` — 2 пробіли.
2. Довжина рядка — не більше ніж 100 символів.
3. Фігурні дужки — стиль Allman (відкривна дужка на новому рядку), обов'язкові навіть для однієї інструкції в тілі `if`.
4. Між членами класу — рівно один порожній рядок.
5. Директиви `using` — на початку файлу, системні перші, невживані видаляються.
6. Простір імен — файлового рівня (`namespace X;`).
7. Файл у кодуванні UTF-8, закінчується одним символом нового рядка, пробілів наприкінці рядків немає.
8. В ініціалізаторі об'єкта кожна властивість стоїть на окремому рядку.

## 4. Коментарі та документація

1. Коментар пояснює «чому», а не «що»; коментар, який переказує код, видаляється.
2. Публічні типи й методи бібліотеки `TaskTracker.Core` мають XML-документацію `<summary>`; автоматична перевірка вмикається з ЛР № 4.
3. Закоментований код у репозиторії не залишається.

```csharp
// погано: коментар переказує код
// додаємо години запису до суми
sum += entry.Hours;

// добре: коментар пояснює причину рішення
// години тримаємо в decimal, щоб 0,25 год (15 хв) не втрачали точність
sum += entry.Hours;
```

## 5. Структура проєкту

1. Уся логіка предметної області живе в `TaskTracker.Core`; `TaskTracker.App` лише вводить і виводить дані.
2. У `TaskTracker.Core` немає викликів `Console.*`.
3. Сутності лежать у теці `Domain`, а простір імен збігається зі шляхом: `TaskTracker.Core.Domain`.
4. Один публічний тип — один файл.
5. `.editorconfig`, `Directory.Build.props`, `.gitignore` лежать у корені поруч із `.sln`.
6. Теки `bin` і `obj` у репозиторій не потрапляють.

## 6. Правила комітів

1. Повідомлення за конвенцією Conventional Commits: `тип: суть`, де тип — `feat`, `fix`, `docs`, `chore` або `style`.
2. Суть — коротка фраза українською, з малої літери, без крапки наприкінці.
3. Один коміт — одна завершена зміна; після коміту проєкт збирається.
4. Повідомлення на кшталт «зміни», «фікс», «робота 1», «asdf» заборонені.
5. Завершення лабораторної роботи позначається міткою `lab1`.

## 7. Правила, закріплені машинно

| Пункт стандарту | Механізм перевірки | Правило |
| --- | --- | --- |
| Відступ 4 пробіли | `.editorconfig` | `indent_size = 4` |
| Приватне поле з `_` | аналізатор іменування | `IDE1006` |
| Дужки обов'язкові | `.editorconfig` | `csharp_prefer_braces` (`IDE0011`) |
| Дужки не пропускаються | StyleCop | `SA1503` |
| Простір імен файлового рівня | `.editorconfig` | `csharp_style_namespace_declarations` (`IDE0161`) |
| Системні `using` першими | `.editorconfig` | `dotnet_sort_system_directives_first` |
| Немає зайвих пробілів | StyleCop | `SA1028` |
| Порядок членів класу | StyleCop | `SA1201` |
| Порожній рядок між членами | StyleCop | `SA1516` |
| UTF-8, кінцевий новий рядок | `dotnet format` | `CHARSET`, `FINALNEWLINE` |
| Формат коду загалом | `dotnet format` | `IDE0055` |

Не перевіряються машинно, тож їх перевіряє рецензент під час огляду коду: довжина рядка (лише лінійка в редакторі), якість коментарів, розподіл логіки між `Core` і `App`, повідомлення комітів.
